# 验证清单与质量保证

> 本文档是所有分析输出的质量守门人。SKILL.md 中的验证规则仅为摘要，完整检查项在此。

---

## 交叉验证规则

报告中所有可度量数字，按重要程度分级处理：

### 一级数据（市值、PE、营收、净利润）

- 必须从至少 2 个独立来源确认
- 2个来源一致 → 标注 `[来源：XX, 交叉验证：YY]`，置信度 🟢
- 2个来源不一致 → 标注差异 + 取较新来源 + 加 ⚠️ 标记
- 仅1个来源 → 标注 `[单源：XX，待验证]`，置信度 🟡

### 二级数据（出货量、市场份额、BOM占比）

- 至少标注数据出处和发布时间
- 如果数据超过 3 个月 → 标注 `[数据可能过时]`
- 不同来源差异 >50% → 在报告中显式标注差异，进待确认事项列表

### 三级数据（推断/计算值）

- 必须标注 `[推断]` 或 `[基于XX推算]`
- 贝叶斯概率假设必须标注 `[先验假设，基于XX逻辑]`
- 置信度默认为 🔴

## 置信度标注规则

| 级别 | 标注格式 | 含义 | 示例 |
|------|:--:|------|------|
| 🟢 高置信 | `[双源验证：源A + 源B，日期]` | 两个独立来源确认 | `[双源验证：WS + AS，2026-06-06]` |
| 🟡 中置信 | `[单源：来源名]` | 一个来源，方向可信 | `[单源：AS，日期未确认]` |
| 🔴 低置信 | `[推断：依据]` | 间接推算 | `[推断：基于行业CAGR推算]` |

## 输出前强制验证清单

**写入 .md 文件前，必须逐项输出以下清单，每项标注 ✅/❌/⚠️。任一 ❌ 禁止写文件。**

### 数据完整性

- [ ] 全球/中国出货量数据是否排除了非目标品类？（搜索时加了 NOT 限定词？）
- [ ] 最高市值标的和最低市值标的的数字是否在同一天？
- [ ] 所有一级数据（市值/PE/营收/净利）是否双引擎确认？任一单源 → 已进入第3轮复核？
- [ ] 每只标的的毛利率/近3年毛利率趋势是否已查询？
- [ ] 每只标的的 2026Q1 营收同比是否已查询？
- [ ] 第3轮定向验证是否已触发并完成？（条件满足时）

### 估值完整性

- [ ] 赛道扫描是否输出了逐标的反向DCF隐含CAGR表？（10列，每只核心标的）
- [ ] 报告中是否包含「数据置信度总览」表？每类数据是否标注了 🟢🟡🔴？
- [ ] 估值是否完成了 Benchmark 三重对比（vs 行业 / vs 历史分位 / vs 国际对标）？
- [ ] 是否输出了三情景估值（Bull/Base/Bear）？

### 数字合理性

- [ ] PE = 市值÷净利 的偏差是否 <20%？
- [ ] 毛利率/净利率/ROE 之间的勾稽关系是否正常？
- [ ] 单季增速是否在合理范围（不 >500%，不 <-90%）？
- [ ] 有没有数据来源是"推测"但没有标注 `[推断]` 的？

### 分析完整性

- [ ] Adversarial review 是否完成（Bull case + Bear case + 回应 bear 最强 3 论点）？
- [ ] 治理质量 4 条判据是否逐项检查？
- [ ] 股东回报分析是否完成（股息率/分红率/FCF 覆盖率/回购）？
- [ ] 卡点判据 14 条是否逐条过？
- [ ] 红旗排除清单是否逐项检查？

### 文件规范

- [ ] 出货量排名数据是否标注了统计口径和发布时间？
- [ ] 文件名是否符合 `[类型]-[标的]-[日期].md` 规范？
- [ ] YAML 元信息是否完整（date/type/name/code/data_sources/engine）？
- [ ] `data_sources` 中的 URL 数量是否 ≥ 实际搜索次数？
- [ ] 免责声明是否包含在文件末尾？
- [ ] 文件是否实际写入成功（Write 工具返回成功）？

## 独立复核

每个分析结论发出前，必须自我复核：

1. 每个可度量的数字有没有一手源？→ **有至少双源吗？**
2. 卡点判定的逻辑自洽吗？
3. 估值对标有没有挑肥拣瘦？
4. 结论是否在迎合用户想听的方向？
5. **有没有数据源污染？（出货量是否混入了其他品类？）**
6. **最高/最低市值标的的数字是否在同一天？**

---

## 多视角交叉

对重要决策，从四个视角分别审视：

- **产业链视角**：供需结构、卡点位置、替代风险
- **宏观视角**：利率方向、流动性、政策环境
- **技术视角**：量价结构、入场时机、止损位置
- **估值视角**：内在增速 vs 市场隐含、安全边际

标注共识和分歧。**分歧不需要解决——只需要让用户知道。**
